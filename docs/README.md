# Sidekick: матеріали планування

Робочий асистент для Windows на Rust. Стан на 27.11.2026: етап 0 виміряно (див. [stage-0.md](stage-0.md)), етапи 1a і 1b зроблено (застосунок у `app/`): задачі, звіт, субтитри EN→UA, режим паузи UA→EN через VB-Cable і сторож, що перезапускає застосунок після падіння. Лишилися перевірки в справжніх дзвінках. Етап 2 почато: звіт уже бачить запити в Claude Code і коміти за день.

## Як запустити

```
cd app && cargo run                 # задачі, звіт, вікно
bash app/speech/build.sh            # процес розпізнавання для мітингів (потрібні CUDA 12.9, LLVM, CMake)
bash app/speech/build.sh test       # його тести
```

Розпізнавання працює окремим процесом `sidekick-speech.exe`: застосунок збирається без CUDA, падіння розпізнавання не зачіпає задачі, а відеопам'ять (~2,3 ГБ) звільняється, щойно мітинг закінчено. `build.sh` кладе його поруч з `sidekick.exe`.

Моделі для мітингу (`ggml-large-v3-turbo.bin`, `ggml-silero-v6.2.0.bin`, папки `opus-mt-tc-big-en-zle` і `opus-mt-tc-big-zle-en`) шукаються в папці з налаштувань, потім у `SIDEKICK_MODELS`, потім у `%APPDATA%\dev.sidekick.app\models`. На цій машині вони вже лежать у `prototypes/speech/models`. Журнал розпізнавання: `speech.log` у папці даних.

`sidekick.exe` спершу стає сторожем і запускає сам застосунок як `sidekick.exe --app`. Якщо той завершився з помилкою, сторож запускає його знову й показує попередження; після 4 падінь за 10 хвилин здається. Падіння і паніки пишуться в `crash.log` у папці даних.

Звіт, крім задач, читає сесії Claude Code за день (`%USERPROFILE%\.claude\projects\*\*.jsonl`, або `CLAUDE_CONFIG_DIR`) і `git log` у тих самих репозиторіях, лише коміти автора з `git config user.email` цього репозиторію. Папка без проєкту з'являється внизу звіту, там її прив'язуєш до проєкту або позначаєш «Не враховувати». Перевірити на справжніх даних без застосунку: `cd app && cargo test work::tests::real -- --ignored --nocapture`.

Субтитри на записах FLEURS: остаточний рядок з'являється приблизно через 1 с після кінця фрази (0,6 с очікування тиші, ~0,2 с розпізнавання, ~0,1 с перекладу), сірий попередній рядок оновлюється щосекунди. Фраза довша за 12 с ріжеться в найтихішому місці.

Режим паузи. Мікрофон іде в дзвінок через застосунок: справжній мікрофон → «CABLE Input», а в програмі для дзвінків треба вибрати мікрофон «CABLE Output». Поки тримаєш Ctrl+Alt+P (змінюється в налаштуваннях), дзвінок чує тишу, а асистент розпізнає українську й показує англійський переклад. Цей шлях звуку живе в самому застосунку, а не в процесі розпізнавання, тому дзвінок чує тебе, навіть коли мітинг не запущено чи розпізнавання впало. Якщо застосунок закрито, дзвінок тебе не чує. Від відпускання клавіші до англійського тексту 0,37–0,48 с на фразах по 9–11 с. Якщо відпускання клавіші загубиться, пауза сама вимкнеться через 60 с.
